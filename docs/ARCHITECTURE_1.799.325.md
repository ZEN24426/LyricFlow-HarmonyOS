# LyricFlow 1.799.325 保存架构

> 历史资料：本文记载 1.799.325 阶段的设计，不代表当前实现或发布状态。请以根目录 README.md 和 RELEASE_CHECKLIST.md 为准。

本工程针对 HarmonyOS API 26。直写是单曲编辑的可选保存方式；默认仍为导出新副本。

## 直写流程

1. 使用 DocumentViewPicker 选择音频并取得该 URI 的临时读写授权。应用不再申请 WRITE_AUDIO；授权失效时须重新选择文件。文件夹功能仍使用其原有的持久授权配置。
2. 导入应用私有工作副本，只提交用户修改的字段。开始前对所选 URI 打开读写句柄，检查文件身份、协作锁，并将其与导入快照逐字节比较。
3. 从同一源句柄创建应用内备份和下载目录备份，校验两份数据。所有标签修改在私有副本中完成；MP3 使用 Mp3DirectWriter，FLAC 使用标签库和 BPM 修正。
4. 回读请求修改的字段，并通过 Id3Integrity 或 FlacIntegrity 比较未编辑标签及音频数据。无法安全处理的文件在更改源文件前拒绝。
5. 同步恢复记录后，通过同一个源句柄提交并逐字节回读。失败时尝试恢复备份；无法确认恢复时保留备份和恢复记录。重启后可以检查记录，用户也可在直写界面重新打开恢复提示。
6. 成功并清除恢复记录后，重新验证下载备份，再清理本次私有备份；不确定时保留私有备份。

源文件就地写入不是原子操作。协作锁不能阻止不遵守锁的其他程序，断电或存储故障仍可能需要用户从备份恢复。

## 格式与验证范围

- MP3 目前支持可安全解析的 ID3v2.3/2.4。特殊标志、重复目标帧、无法保留的描述或日期、多封面和冲突的尾部标签等会拒绝写入。
- FLAC 比较未编辑注释、图片和其他元数据块，以及完整音频帧。某些复杂标签和封面会被拒绝，以免静默丢失信息。
- 普通副本导出仍有独立的格式兼容性要求；不能将直写的原始容器校验结果套用到所有导出格式。
- Mate 80 和 nova 14 Ultra 已使用合成文件验证部分直写、备份和故障恢复场景；nova 还通过系统文件选择器验证了无需 WRITE_AUDIO 的写入。完整发布签名、设备与文件覆盖仍按 [发布前检查清单](../RELEASE_CHECKLIST.md) 执行。
