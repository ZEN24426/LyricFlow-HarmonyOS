LyricFlow 是一个面向 HarmonyOS 7 / API 26 的单曲音频标签与歌词编辑、导出工具。当前分支包含真实文件选择、音频标签处理、歌词解析、文件夹扫描与匹配等实现；**源码已接入这些流程，但尚不能仅凭源码宣称所有设备上均已通过编译和真机验证**。

## 当前功能

### 单曲编辑
- 通过系统文件选择器导入单个音频文件，在应用沙箱副本上处理，避免直接修改导入的源文件。
- 读取和编辑常见音频标签，包括标题、歌手、专辑、年份、曲目序号等字段。
- 封面可从文件或相册选择；应用先读取并显示实际预览，用户确认后才替换当前封面，取消则保留旧封面。
- 导入、粘贴和编辑歌词，并将支持的带时间格式转换为标准 LRC。
- 增强型 LRC 可选择保留编辑区的逐字时间，或导出为普通逐行 LRC；不明确的逐字标记不会被强行转换。
- 在私有音频副本上试听和校时，可预览整首、选定范围或单行偏移，以及使用两个人工确认的时间点修正漂移；确认应用后仍需保存才会修改音频。
- 编辑草稿自动保存文字和歌词；恢复时需重新选择并核对同一音频。草稿不保存封面图片，修改过的封面需重新选择；自动保存失败或进程突然终止时，尚未持久化的编辑不能保证恢复。
- 将编辑后的音频或歌词导出到系统 DOWNLOAD 模式提供的应用下载位置。

### 文件夹匹配
- 通过系统文件夹选择器选择目录，并尝试保存可用的持久授权。
- 扫描可访问目录中的音频、歌词及图片文件。
- 根据文件名、音频标签、歌曲名/歌手拆分及版本标记生成候选匹配。
- 在导出匹配结果前逐项确认、取消或暂缓候选，可返回修改旧选择；扫描本身按只读方式实现，支持进度提示与协作取消。
- 对已确认的匹配，可选择批量写回 MP3/FLAC 原音频中的歌词。开始前需再次选择同一文件夹；每首先创建并校验备份，写入后校验，失败即停止。已成功的歌曲不会随批次失败自动撤销，请保留独立备份。
- 文件夹写入依赖设备和文件提供方实际授予的访问能力；授权或安全检查失败时不会绕过限制，已处理结果和备份会显示在页面中。
- 已优化歌曲名称预处理和歌词候选索引，以减少大型目录中的无关两两比较。

### 云端搜歌词（新增）
- 在单曲编辑或歌词编辑页点击“云端搜歌词”，以当前歌名和歌手作为默认搜索词；首版接入网易云音乐。
- 显示候选的歌名、歌手、专辑、时长及匹配依据。版本冲突、时长冲突、缺少关键标签或接近的候选不会被自动推荐，匹配分不是正确率。
- 推荐只用于突出候选；需主动预览并确认采用歌词。已有歌词会再次询问是否替换，采用后仍需保存音频才会写入文件，不自动修改其他标签。
- 进入页面不会自动联网。主动搜索或预览时，将搜索词或选中歌曲 ID 发往网易云音乐，不上传音频、封面或本地文件路径。详见 [云端搜索与数据使用](docs/CLOUD_LYRICS.md)。
- 搜索与预览可取消。接口不是官方稳定开放 API，可能因网络、地区、限流或服务变更而不可用；失败时保留当前编辑内容，可继续使用本地歌词导入。
- 版本信息和有含义的名称符号会参与推荐保护；文件名回退标题、部分异常搜索结果仅供人工核对。纯音乐提示与损坏的译文会分别处理，并在界面提示。
- 可选择原文、译文或上下排列的原文加译文；同时间点原文在上，未配对行会保留并提示，实际显示效果取决于播放器。
- “只补缺失歌词”提供只读扫描和逐项人工搜索、确认。它会区分可识别的纯文本和时间轴，无法充分检查的内嵌标签标为未知；扫描和确认均不会自动写音频。

## 当前歌词格式

已实现基础解析逻辑的格式：
- **LRC**（包含增强型 LRC 的逐字/逐词时间标记解析尝试）
- **TXT**（纯文本；通常没有逐行时间戳）
- **SRT**
- **VTT**
- **SBV**
- **ASS / SSA**（只保留常见字幕文本与起始时间，复杂样式和卡拉 OK 效果不会完整保留）

**当前不支持 QRC、KRC、YRC 和 TTML。** 文件选择器与文件夹扫描不会把这些格式当作受支持的歌词格式。字幕转为标准 LRC 时，样式和结束时间可能丢失；不明确或混合的字幕内容会拒绝转换。普通逐行 LRC 导出会移除可识别的逐字时间，纯 TXT 不会凭空获得准确的时间戳。

## 工程与验证

- 目标 SDK：HarmonyOS 7 / API 26（工程配置中的 compatible/target SDK 为 26.0.0）。
- 主要实现位于 `entry/src/main/ets/services/`，包括歌词解析、文件选择、音频元数据、文件夹扫描、歌曲名分析和匹配逻辑。
- 音频标签读写由项目内实现，覆盖部分 MP3（无标签或 ID3v2.3/2.4）、FLAC、标准 RIFF/WAV、未压缩 AIFF、有固定标签空间的单轨 M4A、单流 OGG/OPUS，以及部分 ADTS AAC-LC 文件。除 MP3、FLAC 外仅支持副本导出；OGG/OPUS 封面暂不可更换，含冲突标签或不支持结构的文件会拒绝写入。AAC 仅支持无 CRC、单原始数据块、单声道或立体声的部分 ADTS 文件；时长为系统估算，添加 ID3 后的兼容性因播放器而异。WMA 仅支持部分单音轨 ASF 文件的副本导出；结构、预留空间、字段、封面及 CUSTOM 色域等限制见 [WMA 说明](docs/WMA-ASF.md)。含 CUSTOM 色域原封面的文件即使只改文字也可能拒绝。更多文件及设备仍需验证。
- 文件夹扫描和下载目录行为会受系统版本、设备形态及系统文件访问授权影响；手机、平板与二合一设备的能力不应一概而论。
- 旧版去依赖实现在 API 26 真机上用独立调试包及合成音频进行过部分验证；本开发版的合并结果、正式签名 Release 包及更多设备、音频仍需分别回归。详见 [去依赖验证记录](docs/TAGLIB_REMOVAL_STATUS.md)。
- 新增云端功能的算法/接口测试与真机回归记录见 [云端功能说明](docs/CLOUD_LYRICS.md)；旧版直写验证不代表云端流程已经完成设备验收。

## 在 DevEco Studio 中打开

1. 使用支持 HarmonyOS 7 / API 26 的 DevEco Studio。
2. 选择 **Open Project** 并打开本仓库。
3. 使用本机安装的 API 26 SDK 同步工程。
4. 在 DevEco Studio 中配置本机签名后，在目标设备或模拟器上构建并运行；调试可使用 **File > Project Structure > Project > Signing Configs > Automatically generate signature**。

项目仓库不包含个人签名配置。首次拉取或本机构建配置被覆盖后，必须重新配置本机签名，否则构建可能只有 unsigned HAP，安装会出现 `no signature file`。请按 [本机签名配置](docs/LOCAL_SIGNING.md) 检查签名方案与 product 引用，并使用实际签名的 HAP 安装；发布需使用对应渠道的正式发布签名。

## 导出与完整性校验

- 使用系统 `DocumentViewPicker` 的 `DOWNLOAD` 模式，直接在该模式返回的应用下载位置保存文件，不额外创建 `LyricFlow` 子目录。
- 若下载位置已有同名文件，通常会自动添加 (1)、(2) 等编号；不会直接改写导入的源音频。但检查名称与创建文件不是跨进程原子操作，同目录并发写入时仍有同名竞争，详见 [发布检查清单](RELEASE_CHECKLIST.md)。
- 写入并关闭文件后，歌词/文本按字节回读比对；音频以分块方式与最终待导出的沙箱副本逐字节比对，避免整首音频载入内存。
- 音频副本在导出前回读请求写入的标签，并检查未编辑字段和音频数据的保全；不能安全确认时停止导出。
- 访问权限、URI 或目录访问错误会重新请求一次 DOWNLOAD URI；存储空间不足、内容比对不一致等错误不会盲目重复请求。
- 去依赖实现尚未恢复旧库的全部格式兼容性；有限样本测试不代表所有格式或设备均通过发布回归。
