LyricFlow 是一个面向 HarmonyOS 7 / API 26 的单曲音频标签与歌词编辑、导出工具。当前分支包含真实文件选择、音频标签处理、歌词解析、文件夹扫描与匹配等实现；**源码已接入这些流程，但尚不能仅凭源码宣称所有设备上均已通过编译和真机验证**。

## 当前功能

### 单曲编辑
- 通过系统文件选择器导入单个音频文件，在应用沙箱副本上处理，避免直接修改导入的源文件。
- 读取和编辑常见音频标签，包括标题、歌手、专辑、年份、曲目序号等字段。
- 封面可从文件或相册选择；应用先读取并显示实际预览，用户确认后才替换当前封面，取消则保留旧封面。
- 导入、粘贴和编辑歌词，并将支持的带时间格式转换为标准 LRC。
- 将编辑后的音频或歌词导出到系统 DOWNLOAD 模式提供的应用下载位置。

### 文件夹匹配
- 通过系统文件夹选择器选择目录，并尝试保存可用的持久授权。
- 扫描可访问目录中的音频、歌词及图片文件。
- 根据文件名、音频标签、歌曲名/歌手拆分及版本标记生成候选匹配。
- 在导出匹配结果前逐项确认、取消或暂缓候选，可返回修改旧选择；扫描本身按只读方式实现，支持进度提示与协作取消。
- 对已确认的匹配，可选择批量写回 MP3/FLAC 原音频中的歌词。开始前需再次选择同一文件夹；每首先创建并校验备份，写入后校验，失败即停止。已成功的歌曲不会随批次失败自动撤销，请保留独立备份。
- 文件夹写入依赖设备和文件提供方实际授予的访问能力；授权或安全检查失败时不会绕过限制，已处理结果和备份会显示在页面中。
- 已优化歌曲名称预处理和歌词候选索引，以减少大型目录中的无关两两比较。

## 界面与交互

- 使用页面顶部的“单曲编辑”和“文件夹匹配”切换工作模式。

## 当前歌词格式

已实现基础解析逻辑的格式：
- **LRC**（包含增强型 LRC 的逐字/逐词时间标记解析尝试）
- **TXT**（纯文本；通常没有逐行时间戳）
- **SRT**
- **VTT**
- **SBV**
- **ASS / SSA**（只保留常见字幕文本与起始时间，复杂样式和卡拉 OK 效果不会完整保留）

**当前不支持 QRC、KRC、YRC 和 TTML。** 文件选择器与文件夹扫描不会把这些格式当作受支持的歌词格式。导出为标准 LRC 时，源格式的样式、结束时间或逐字时间等信息可能丢失；纯 TXT 不会凭空获得准确的时间戳。

## 工程与验证

- 目标 SDK：HarmonyOS 7 / API 26（工程配置中的 compatible/target SDK 为 26.0.0）。
- 主要实现位于 `entry/src/main/ets/services/`，包括歌词解析、文件选择、音频元数据、文件夹扫描、歌曲名分析和匹配逻辑。
- 音频标签读写由项目内实现，现阶段覆盖部分 MP3（无标签或 ID3v2.3/2.4）、FLAC、标准 RIFF/WAV、未压缩 AIFF、有固定标签空间的单轨 M4A、单流 OGG/OPUS，以及部分 ADTS AAC-LC 文件。除 MP3、FLAC 外仅支持副本导出；OGG/OPUS 封面暂不可更换，含冲突标签或不支持结构的文件会拒绝写入。AAC 仅支持无 CRC、单原始数据块、单声道或立体声的部分 ADTS 文件；时长为系统估算，添加 ID3 标签后的兼容性因播放器而异。WMA 尚未恢复支持，复杂标签及更多设备仍需验证。
- 文件夹扫描和下载目录行为会受系统版本、设备形态及系统文件访问授权影响；手机、平板与二合一设备的能力不应一概而论。
- 已在 API 26 真机上用独立调试包及合成音频进行部分验证；仍需在正式签名 Release 包和更多设备、音频上完成回归。

## 在 DevEco Studio 中打开

1. 使用支持 HarmonyOS 7 / API 26 的 DevEco Studio。
2. 选择 **Open Project** 并打开本仓库。
3. 使用本机安装的 API 26 SDK 同步工程。
4. 在 DevEco Studio 中配置本机签名后，在目标设备或模拟器上构建并运行；调试可使用 **File > Project Structure > Project > Signing Configs > Automatically generate signature**。

项目仓库不包含个人签名配置。首次拉取或本机构建配置被覆盖后，必须重新配置本机签名，否则构建可能只有 unsigned HAP，安装会出现 `no signature file`。请按 [本机签名配置](docs/LOCAL_SIGNING.md) 检查签名方案与 product 引用，并使用实际签名的 HAP 安装；发布需使用对应渠道的正式发布签名。

## 导出与完整性校验

- 使用系统 `DocumentViewPicker` 的 `DOWNLOAD` 模式，直接在该模式返回的应用下载位置保存文件，不额外创建 `LyricFlow` 子目录。
- 若下载位置已有同名文件，将自动添加 (1)、(2) 等编号，不主动覆盖已有导出；不会直接改写导入的源音频。
- 写入并关闭文件后，歌词/文本按字节回读比对；音频以分块方式与最终待导出的沙箱副本逐字节比对，避免整首音频载入内存。
- 音频副本在导出前回读请求写入的标签，并检查未编辑字段和音频数据的保全；不能安全确认时停止导出。
- 访问权限、URI 或目录访问错误会重新请求一次 DOWNLOAD URI；存储空间不足、内容比对不一致等错误不会盲目重复请求。
- 该验证版还未恢复旧库的全部格式兼容性；请勿将有限样本测试视为完整发布回归。
